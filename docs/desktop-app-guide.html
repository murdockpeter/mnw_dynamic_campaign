Overview

What This App Is For

The desktop app is a packaged frontend and workflow wrapper for the dynamic campaign tooling in this repo.

It lets you
  • Configure where Modern Naval Warfare stores campaign packages.
  • Generate a simple multi-scenario campaign without bringing your own AI.
  • Build and deploy the generated campaign package.
  • Inspect campaign runtime state.
  • Ingest mission-result JSON after missions.
You do not need
  • Python
  • PowerShell
  • Node.js
  • npm
  • AI tooling

Install

What To Install

Windows

Use MNW Dynamic Campaign Console Setup 0.1.3.exe.

macOS

Use the packaged .dmg release once one is provided.

Important

If someone gives you the source repo instead of the packaged installer, that is the developer version, not the player-first install path.

Setup

First Launch

When the app starts for the first time, go to Setup.

You will be asked for
  • Game Campaign Path
  • User Campaign Path
  • Preferred Runtime Campaign ID
  • Preferred Package ID
  • Optional package source and output paths
Tip

On first launch the app will try to detect these paths automatically. Use Find Paths again if you want to rescan before saving.

Typical Windows Paths
C:\Program Files (x86)\Steam\steamapps\common\Modern Naval Warfare\Var\Scenarios\Packages\Campaigns
C:\Users\<YourUser>\AppData\LocalLow\WaveOps\ModernNavalWarfare\Scenarios\Packages\Campaigns

The Find Paths button can also fill the package source and output paths from the app workspace.

App Layout

Understanding The Three Workspaces

1
Setup

Use this once to configure paths and defaults.

  • Installed game campaign package path
  • User profile campaign package path
  • Default runtime campaign ID
  • Default package ID
2
Authoring

Use this to create and package campaigns.

  • Choose campaign title, ID, theater, campaign climate, mission type, and scenario count.
  • Preview the generated campaign blueprint.
  • Write campaign files, build the package, and deploy it.
  • Review the pathing model and platform-selection model.
3
Campaign Tracking

Use this after missions.

  • Inspect the campaign summary.
  • Inspect tracked units and persistence modules.
  • Review recent result data and next-mission directives.
  • Build manual result JSON or parse debrief text into a draft result.
Important

Campaign Tracking uses real exported runtime data only. If no runtime snapshot exists yet, the app shows instructions instead of fake sample state.

Identifiers

Campaign ID vs Package ID

These usually match.

Campaign ID

The runtime campaign identifier used by the tracker and persistence flow.

Package ID

The MNW package identifier used for build and deploy.

Typical simple usage

campaign ID: iron_archipelago

package ID: iron_archipelago

iron_archipelago.iron_archipelago.bashi_screen

Only split these IDs if you intentionally know you are tracking one campaign state while building another package tree.

Generator

How The Generator Works Without AI

The generator is deterministic and rule-based. It does not call an AI model.

It uses
  • Theater templates
  • Side templates
  • Mission archetype sequences
  • Seeded variation
Result

The same inputs always produce the same campaign.

Pathing
  1. Choose a mission sequence based on the selected campaign climate.
  2. Create a stable seed from your campaign settings.
  3. Jitter corridor anchor points within bounded limits.
  4. Derive spawn points, contact datums, escorts, barrier or egress points, and withdrawal legs.
  5. Advance timing and contact density across later scenarios.
Platform Selection

Theater choice drives side selection and baseline units.

  • Luzon Strait: U.S. submarine vs PLAN surface combatants
  • South China Sea: U.S. submarine vs Russian submarines

Tone changes scenario sequence and pacing. It does not swap the sides or the theater family.

Workflow

Typical Use Flow

1
Initial setup

Install the desktop app, open Setup, use Find Paths, review the detected MNW paths, and save settings.

2
Authoring pass

Open Authoring, preview a campaign, write campaign files, build the package, and deploy the package.

3
Play in MNW

Launch MNW and play the generated campaign.

4
Export runtime state

Return to Authoring and use Export Runtime Snapshot once the campaign exists in MNW.

5
Track and ingest

Open Campaign Tracking to inspect real state, then ingest result JSON after each mission.

Troubleshooting

If Something Looks Wrong

  • Check that the game path is correct.
  • Check that the user campaign path is correct.
  • Check that the runtime campaign ID and package ID are what you intend.
  • Check that the package was built before deployment.
  • Check that the package was deployed after the latest build.
Most common cause

If the app launches but cannot find campaign files, the usual issue is a path or ID mismatch.

Modern Naval Warfare

Repo Tool Reference

This page explains what each script in tools/ does, when to use it, and the exact command shape to run. It is focused on the real repository tooling, not generic AI advice.

Primary Use

Build, deploy, inspect, ingest, and serve the dynamic campaign workflow from one repo.

Audience

Operators, mod authors, and AI coding agents working locally against this project.

Assumptions

Windows, PowerShell, Python, and a local Modern Naval Warfare install for game-facing steps.

How To Read This

PowerShell Wrappers

Most repo entry points are .ps1 scripts intended to be run from the repo root.

Python Helpers

Two Python scripts handle campaign-state export and mission-result ingestion behind the PowerShell wrappers.

Operator Rule

Prefer the wrapper scripts unless you specifically need the lower-level Python entry point.

Recommended Workflow

1

Validate and build

Use build.ps1 directly, or let run-dev.ps1 do it for you.
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1
2

Deploy to the game

Copy the built .kyt into the game and LocalLow campaign folders.
powershell -ExecutionPolicy Bypass -File .\tools\deploy.ps1
3

Export and inspect state in the UI

Start the local UI after tests and state export.
powershell -ExecutionPolicy Bypass -File .\tools\run-dev.ps1
4

Ingest mission results and refresh the snapshot

Turn a normalized result JSON into persisted campaign updates.
powershell -ExecutionPolicy Bypass -File .\tools\ingest-and-refresh.ps1 -ResultPath ".\parsers\manual_result_followup.json"

Tool Reference

Build

tools/build.ps1

Builds a valid MNW .kyt package from a source package tree.

What it does: Recalculates manifest.json MD5 hashes, rewrites the manifest, creates ZIP entries with forward-slash paths, and outputs the final package hash.
Default input: src/package/
Default output: dist/norwegian_shadow.kyt 
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1

powershell -ExecutionPolicy Bypass -File .\tools\build.ps1 `
  -SourceDir .\src\packages\iron_archipelago `
  -OutputPath .\dist\iron_archipelago.kyt

Use this after any mission, campaign, locale, sidecar, or manifest-relevant package change.

Deploy

tools/deploy.ps1

Copies a built package into the main game install and the LocalLow user campaign folder.

What it does: Ensures target directories exist, copies the selected .kyt, and prints MD5 hashes for the source and both deployed copies.
Default package: dist/norwegian_shadow.kyt 
powershell -ExecutionPolicy Bypass -File .\tools\deploy.ps1

powershell -ExecutionPolicy Bypass -File .\tools\deploy.ps1 `
  -PackagePath .\dist\iron_archipelago.kyt

Use this after every rebuild you intend to test in-game. The printed hashes are part of the validation path.

DB Index

tools/index-db.ps1

Scans the user's local MNW .core and .ais archives and writes machine-friendly summaries.

What it does: Inventories entries, groups by extension and top-level folder, samples readable strings from .msg files, and writes JSON plus CSV under generated/db/. 
powershell -ExecutionPolicy Bypass -File .\tools\index-db.ps1

powershell -ExecutionPolicy Bypass -File .\tools\index-db.ps1 `
  -DbDir "C:\Program Files (x86)\Steam\steamapps\common\Modern Naval Warfare\Var\DB" `
  -OutputDir .\generated\db

Use this when you want local archive inventory for research, prompt context, or follow-up tooling. It does not redistribute game data.

Run UI

tools/run-ui.ps1

Serves the repo root with Python's built-in HTTP server so the UI can run in a browser.

What it does: Verifies the UI files exist, optionally opens the browser, and serves ui/index.html at http://localhost:<port>/ui/index.html. 
powershell -ExecutionPolicy Bypass -File .\tools\run-ui.ps1

powershell -ExecutionPolicy Bypass -File .\tools\run-ui.ps1 -Port 8765 -OpenBrowser

Use this when you only need the browser UI and do not want the full validate-build-export flow.

Run Dev

tools/run-dev.ps1

Convenience entry point for the normal development loop.

What it does: Runs the persistence smoke test, builds the default package, exports live UI state, then starts the local UI server. 
powershell -ExecutionPolicy Bypass -File .\tools\run-dev.ps1

powershell -ExecutionPolicy Bypass -File .\tools\run-dev.ps1 -SkipTests -NoBrowser

powershell -ExecutionPolicy Bypass -File .\tools\run-dev.ps1 -Port 9000

Use this when you want one command to prep the UI against current backend state before working in the browser.

Refresh UI

tools/refresh-ui-state.ps1

Refreshes the exported runtime snapshot consumed by the UI.

What it does: Calls tools/export-ui-state.py for the selected campaign ID. 
powershell -ExecutionPolicy Bypass -File .\tools\refresh-ui-state.ps1

powershell -ExecutionPolicy Bypass -File .\tools\refresh-ui-state.ps1 -CampaignId silent_meridian

Use this after state changes when you do not need the full ingest wrapper or dev server flow.

Export State

tools/export-ui-state.py

Builds a UI-friendly JSON snapshot from campaign config, persisted state, latest result, and generation directives.

What it does: Loads or bootstraps campaign state, loads the latest mission result, runs the persistence runtime, infers a next-mission placeholder, and writes generated/ui/runtime.json by default. 
python .\tools\export-ui-state.py

python .\tools\export-ui-state.py --campaign-id silent_meridian

python .\tools\export-ui-state.py --campaign-id silent_meridian --output .\generated\ui\runtime.json

Use this directly if you are automating export from another tool or script.

Ingest

tools/ingest-result.py

Applies a normalized mission-result JSON to persisted campaign state.

What it does: Loads the campaign modules, reads the current state, ingests one result, advances campaign time, sets the current mission ID, saves state, and appends the result to history. 
python .\tools\ingest-result.py `
  --campaign-id silent_meridian `
  --result .\parsers\manual_result_followup.json `
  --advance-hours 24

Use this lower-level script when you want state ingestion without automatically exporting a fresh UI snapshot.

Ingest + Refresh

tools/ingest-and-refresh.ps1

Operator wrapper for the post-mission persistence loop.

What it does: Runs ingest-result.py, then immediately runs refresh-ui-state.ps1 so the browser UI reflects the updated state. 
powershell -ExecutionPolicy Bypass -File .\tools\ingest-and-refresh.ps1

powershell -ExecutionPolicy Bypass -File .\tools\ingest-and-refresh.ps1 `
  -CampaignId silent_meridian `
  -ResultPath .\parsers\manual_result_example.json `
  -AdvanceHours 12

Use this after each played mission once you have a reviewed normalized result JSON.

Report

tools/report-repo.ps1

Generates an HTML report that explains what files in the repo are for.

What it does: Walks the repo, categorizes files, applies purpose descriptions, and writes a styled HTML report under generated/reports/ by default. 
powershell -ExecutionPolicy Bypass -File .\tools\report-repo.ps1

powershell -ExecutionPolicy Bypass -File .\tools\report-repo.ps1 -GitVisibleOnly

powershell -ExecutionPolicy Bypass -File .\tools\report-repo.ps1 -BrightTheme

Use this when you want a shareable inventory of repo structure or need to re-document the file surface after larger changes.

Practical Guardrails

Rebuild First

Do not deploy stale content. If package files changed, run build.ps1 before deploy.ps1.

Trust Hashes

Use the MD5 output from build and deploy to verify the exact package you tested is the one you built.

Use Wrappers

Prefer run-dev.ps1 and ingest-and-refresh.ps1 unless you specifically need lower-level scripting control.

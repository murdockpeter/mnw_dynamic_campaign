Overall App Scope

What The Desktop App Does Today

The app is split into three real workspaces and is meant to cover the full campaign loop around MNW without pretending to be the game itself.

Setup

Find MNW paths, store defaults, configure campaign and package IDs, and optionally enable AISStream.

Authoring

Generate deterministic campaigns, write package files, build the `.kyt`, deploy it, and monitor the workflow.

Campaign Tracking

Inspect exported runtime state, save mission results, parse debrief text, refresh AIS samples, and continue the campaign.

Persistence Model

Track state outside MNW using JSON so the dynamic campaign logic can evolve without modifying the game’s native save structure.

No AI required for baseline generation
Electron desktop app for setup, build, deploy, and tracking
Real runtime data only in Campaign Tracking

Workspace 1

Setup

The setup page is now meant to be usable by testers who are not comfortable with Windows paths.

Automatic Path Detection

  • Attempts to detect the installed MNW game campaign folder.
  • Attempts to detect the user campaign folder under the local Windows profile.
  • Fills the package source and output paths from the app’s writable workspace.
  • Runs automatically on first launch if the path fields are empty.

Manual Recovery

  • Find Paths reruns detection manually.
  • Save Desktop Settings persists the final values.
  • Use Latest Generated Campaign repoints setup defaults to the latest authored package tree.

Saved Defaults

  • Game campaign path
  • User campaign path
  • Preferred runtime campaign ID
  • Preferred package ID
  • Preferred package source dir
  • Preferred package output path

AIS Settings

  • Enable or disable AISStream access
  • Store AIS API token locally in desktop settings
  • Set the query radius used for live contact pulls
  • Keep AIS credentials out of generated campaign package files

Workspace 2

Authoring

Authoring is for building a campaign package end to end, not for editing runtime state after play.

Campaign Wizard Inputs

  • Campaign title and campaign ID
  • Theater
  • Campaign climate
  • Mission type
  • Scenario count
  • Mission stance
  • Rules of engagement
  • Start year
  • Player unit name
  • Optional max scenario radius constraint

Authoring Actions

  • Write Campaign Files
  • Build Package
  • Deploy Package
  • Start Over
Authoring flow guidance

The app includes a step-driven workflow view that indicates whether setup is saved, files are written, the package is built, the package is deployed, and whether a runtime snapshot is ready to inspect.

Package Generation

  • Writes campaign source files into the workspace package tree.
  • Builds a `.kyt` package for MNW.
  • Deploys the package into game and user campaign folders if configured.

Campaign Bootstrap

  • Initializes Campaign Tracking state for the first mission.
  • Creates the persistence files needed for follow-on runtime tracking.
  • Preserves a reserved next mission slot for continuation flow.

Workspace 3

Campaign Tracking

Campaign Tracking now shows real exported runtime state only. It does not load fake sample data anymore.

Runtime Summary

  • Campaign, theater, current mission, and campaign clock
  • Campaign climate, mission type, mission stance, ROE, escalation
  • Experimental feature state when applicable

Persistence Summary

  • Enabled modules
  • Tracked units and readiness
  • Damage and ammo persistence
  • Mission-history driven next-step generation

Mission Result Tools

  • Manual result builder
  • Debrief-text parser into draft result payloads
  • Save result directly and refresh tracking state

Continuation Tools

  • Continue Campaign by rewriting the reserved next mission
  • Keep one additional reserved slot chained behind it
  • Regenerate tasking, geometry, and support bias from the latest result

Operational Context

  • Embedded theater operational map links
  • Order of battle and theater debug view
  • Runtime snapshot export and reload support

Live AIS Feed

  • Optional AISStream pull from the backend only
  • Live contact sampling around the current theater center
  • Debug payload display for what the feed returned

Generator And Mission Logic

What The Campaign Generator Currently Models

The campaign generator is deterministic and rule-based. It does not require an LLM to create the baseline missions.

Area What It Does Tester-Relevant Result
Campaign Climate Sets the opening political and operational state of the arc. Players start in peacetime patrol, high alert, or open warfare conditions instead of a generic tone label.
Escalation Tracks peacetime, heightened_tension, crisis, and open_warfare. Briefings, tension settings, mission framing, and continuation behavior reflect prior outcomes.
ROE Separates engagement authority from mission type. A surveillance mission can still occur under tense rules, and attack authority is spelled out explicitly.
Mission Orders Builds clearer primary task, target, expected action, and end-state language. Testers should be able to answer what they are looking for, what they may shoot, and what ends the mission.
Command Flavor Uses theater command authorities such as COMSUBPAC and COMSUBLANT. Completion and command text are less generic.
Continuation Builds follow-on missions from saved result state. Mission N+1 should feel like a response to Mission N instead of a disconnected reroll.
AIS Seeding Can bias some civilian merchant traffic from live AIS samples. Optional real-world civilian traffic flavor is available when AIS is enabled.

Experimental Track

What Is Behind The Toggle Right Now

Experimental content is intentionally gated in the UI so testers can turn it on or off if it causes interim issues.

Implemented

Curated plot seeds are available and intentionally replace any idea of open-ended movie or news scraping.

Partial

spec_ops, counter_piracy, and counter_terror are tracked as experimental mission families.

Still Limited

Experimental mission families currently bias briefings and force mix but do not yet have fully bespoke MNW mission-script families.

Current Plot Seeds

  • Grey-Zone Smuggling Crackdown
  • Hostage Recovery Window
  • Blockade Relief Corridor
  • Littoral Special Recon

Land Attack Status

land_attack is still intentionally gated because it is not technically supported by the current generator and MNW mission-script pipeline. It falls back safely instead of claiming support it does not have.

Current Limits

What Beta Testers Should Understand Up Front

Not Yet A Full Dynamic War Engine

The persistence system is real, but the gameplay ruleset is still a scaffold compared to a mature simulation campaign layer.

No Full Bespoke Mission Families Yet

Several mission families are still implemented as meaningful biasing layers rather than totally distinct authored mission frameworks.

Installer QA Still Matters

The first-launch path detection and setup flow still benefit from broad testing on clean user machines.

Important

The app’s goal right now is to make campaign authoring, deployment, and state tracking workable and understandable. It is not claiming that every future mission family or warfare domain is fully realized yet.

Tester Notes

What Feedback Is Most Useful Right Now

Usability

  • Did setup-path detection work without confusion?
  • Were the setup, authoring, and tracking workspaces easy to understand?
  • Did the workflow steps make it obvious what to do next?

Mission Clarity

  • Was the primary task obvious?
  • Was engagement authority obvious?
  • Was the end condition obvious?

Campaign Continuity

  • Did the next mission feel connected to the last result?
  • Did escalation and ROE shifts feel believable?
  • Did command flavor and targeting orders feel plausible?

Experimental Track

  • Did the experimental plot seeds add useful flavor?
  • Did the warnings make the experimental limitations clear enough?
  • Would you keep the experimental toggle visible in normal use?
